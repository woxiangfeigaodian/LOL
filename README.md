# 内鬼模式（LoL 内战版）

给 5v5 内战用的内鬼分配 + 赛后投票网页。10 个人各开各的页面，靠一个 4 位房间码进同一间房；
**全部身份只存在服务端，接口只把「你自己的身份」下发给你本人**，别人在任何网络响应里都查不到你的角色。

零依赖：只用 Node 内置模块，不需要 `npm install`，没有构建步骤。

## 两种模式

建房时选择模式，房间建好后不能中途更换：

- **经典模式（默认）**：两队各一名内鬼，规则见下。
- **多内鬼模式**：每队随机 2~5 名内鬼（两队数量相同），每人 2 票，平民投本队、内鬼猜对面。

首页选完模式后点「查看规则」，或者房间内点顶栏的「规则」，都会弹窗展示当前模式的完整规则
（身份、投票、判定、红包结算，按模式各自写明）。

### 经典模式

- 1–5 号是 A 队，6–10 号是 B 队，**每队各随机一名内鬼**。
- 两个内鬼**互相不知道**对方是谁。
- 身份只有本人能看到，猜不到也查不到别人的。
- 游戏结束后**队内投票**，每人只能投本队其他人，不能投自己。
- 内鬼不能投本队的人，**改成在对面队伍那 5 个人里猜谁是对面的内鬼**，并且**这一票计入对面队伍的票数**。
  所以每队最终是 5 票：本队 4 个平民的票 + 对面内鬼猜过来的 1 票。
  猜中就是给对面内鬼加一票——两个内鬼互相不知道对方是谁，只能盲猜。
- **唯一最高票正好是内鬼** → 平民胜出；**平票 / 最高票是平民 / 无人投票** → 内鬼胜出。
- **允许连续当内鬼**，每轮完全独立随机，不做任何排除。
- 结算页列出**每个人投给了谁**，内鬼那一票单独高亮标出；每轮的内鬼和结果都会存进**历史战绩**，
  之后随时能展开回看（默认收起，最近的一轮在最上面）。
- 结算页有**比赛结果录入 + 红包清单**（房主操作，单倍结算，暂不含「被投出双倍」）：
  - 内鬼所在队赢了，或者内鬼被投出 → 内鬼发 **5 个红包（共 5 元）**，
    由**己方 4 个平民 + 对方内鬼**共 5 人领取，一人 1 元；
  - 内鬼所在队输了且没被投出 → 内鬼免罚，**己方没投中他的平民每人给他 1 元**（弃权也算没投中）。
  - 比赛结果在投票阶段或结算阶段都能录；**录错了可以点另一边改，也可以「撤回」重录**，
    清单和历史战绩会跟着实时重算 / 清空。

### 多内鬼模式

- **每队随机 2~5 名内鬼，两队数量相同**，每轮开始重新随机。
- 赛后**每人 2 票、一次提交**（不能投自己，两票必须投给两个不同的人）：
  平民两票都投本队；内鬼不能投本队，两票都去猜对面队伍的内鬼。
- 和经典模式一样，**内鬼的票计入对面队伍的票数**。全员投完时每队恒为 10 票
  （本队平民每人 2 票 + 对面内鬼每人 2 票），不会随内鬼数量浮动。
- 结算公布**全部内鬼名单、每队票数排行、完整票型（谁投了谁，内鬼票单独标出）**，
  并单独标出**票数最高的内鬼**；内鬼猜中对面内鬼的那一票会带 🎯。
- 结算页同样有**比赛结果录入 + 自动红包清单**（房主在投票阶段或结算阶段点 A 队赢 / B 队赢）：
  - 内鬼所在队赢了，或该内鬼被投出（**本队最高票里的内鬼，可并列**）→ 每个内鬼发 **5 个红包**，
    总额 = **6 − 内鬼数量**（5 人局 1 元 / 4 人局 2 元 / 3 人局 3 元 / 2 人局 4 元）；
    领包人 = **己方平民 + 对方内鬼**，共 5 人。
  - 内鬼所在队输了且没被投出 → 该内鬼**免罚**，什么都不用发。
  - **平民不参与发红包**（多内鬼模式没有"漏投给内鬼 1 元"这类反向转账）。

## 本机跑起来（30 秒）

需要 Node 18 或更高版本。

```bash
cd lol-spy
node server.js
```

打开 http://localhost:3000 就能用。Windows 上也可以直接双击 `start-windows.bat`。

局域网内其他人访问 `http://你的内网IP:3000`（注意放行防火墙）。要让外网的朋友进来，看下面的部署部分。

## 部署到公网

> 想直接拿到一个"发给谁都能用"的网址，照着 [DEPLOY.md](DEPLOY.md) 走就行，那份是按步骤点的清单。

### 路线 1：Render 免费实例（推荐，长期可用）

1. 把 `lol-spy` 目录推到一个 GitHub 仓库（公开或私有都行）。
2. 到 [render.com](https://render.com) 注册（可以直接用 GitHub 账号登录）。
3. 点 `New +` → `Web Service`，选上刚才的仓库，然后填：
   - **Runtime**：`Node`
   - **Build Command**：留空（没有依赖要装）
   - **Start Command**：`node server.js`
   - **Instance Type**：`Free`
4. 等一分多钟，拿到形如 `https://lol-spy-xxxx.onrender.com` 的地址，发群里就行。

仓库里带了一份 `render.yaml`，用 `New +` → `Blueprint` 选仓库也能直接读这份配置。

免费实例的两点注意：

- **15 分钟没人访问会休眠**，下一次访问要等 30–60 秒冷启动。游戏进行时只要有人开着页面（哪怕在后台标签页），轮询就会让它保持清醒。
- **休眠唤醒或重新部署都会清空内存里的房间**，那个房间码随之失效，重新开一间即可。
- **必须保持单实例**，不要开多实例 —— 房间状态在内存里，多实例会各存一份。

### 路线 2：零注册，房主本机开 + 隧道（最快）

不用注册任何账号，适合临时开黑：

```powershell
# 1) 本机启动服务
node server.js

# 2) 另开一个窗口，装隧道工具并穿透（Windows）
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:3000
```

终端会打印一个 `https://xxxx.trycloudflare.com` 地址，把它发群里。
缺点是房主电脑必须一直开着，而且隧道地址每次重启都会变。

### 路线 3：Docker / 其它云主机

仓库带 `Dockerfile`，任何支持容器或 Node 的平台（Fly.io、Railway、Zeabur、腾讯云轻量、阿里云等）都能跑：

```bash
docker build -t lol-spy .
docker run -p 3000:3000 lol-spy
```

服务读取 `PORT` 环境变量，默认 3000。

## 一局怎么走

1. 房主点「创建房间」，**先选模式（经典 / 多内鬼）**，把房间码或邀请链接发群里。加入的人会自动跟随房间模式。
2. 其他人打开链接（房间码会自动填好）→ 选一个空座位 → 填昵称 → 加入。
3. 10 个人到齐后，房主点「开始第 1 轮」。经典模式每队随机出一名内鬼；
   多内鬼模式每队随机出 2~5 名内鬼（两队数量相同），每轮重新随机。
4. 每个人点开「点击查看我的身份」看自己的角色，点「我记住了，确认身份」，然后**就可以去开游戏了** —— 这一步只是发牌。
5. 打完回来，房主点「进入投票阶段」（要等 10 个人都确认过身份这个按钮才会亮）。
6. 投票：经典模式里平民投本队，**内鬼改成在对面队伍 5 人里猜谁是对面的内鬼**（这一票计入对面队伍的票数）；
   多内鬼模式里**每人 2 票、一次提交，要投两个不同的人**——平民两票都投本队，内鬼两票都猜对面。
   提交后不能改，投票过程中**不显示任何票数**，避免跟风。
7. 10 个人都投完会自动结算；也可以由房主「提前结束投票」，没投的按弃权处理。
8. 结算页显示两队的票数排行、真正的内鬼是谁、**每个人投给了谁**的完整票型（内鬼的票单独高亮）。
   经典模式还会给出判定结果和两个内鬼互猜的结果；多内鬼模式会标出**票数最高的内鬼**（含并列情况），
   并给出两队各自的票数明细。
9. 打完真实比赛后，房主在结算页（投票阶段也可以）点一下**A 队赢 / B 队赢**，App 自动生成**红包清单**：
   - 经典模式（单倍，暂不含双倍）：赢队内鬼或被投出的内鬼发 5 个红包（共 5 元），己方平民 + 对方内鬼一人领 1 元；
     输了又没被投出的内鬼免罚，反过来由没投中他的平民每人给他 1 元。
   - 多内鬼模式：每个受罚内鬼发 5 个红包，总额 = 6 − 内鬼数量（5 人 1 元 / 4 人 2 元 / 3 人 3 元 / 2 人 4 元）；
     平民不参与，输了又没被投出的内鬼免罚。
10. 房主点「开始新一轮」→ 重新随机内鬼，所有人自动回到看身份页面，**不用重新加房间**。

## 常见问题

**刷新页面会丢身份吗？**
不会。座位和身份绑定在浏览器的本地存储上，同一个浏览器打开同一地址会自动回到房间。

**换设备 / 清了浏览器数据怎么办？**
换设备后拿不回原来的座位，得让房主在大厅或结算阶段点座位右上角的 `×` 清空，然后再加入。

**有人中途退赛怎么办？**
房主可以在大厅、看身份、结算阶段清空那个座位。在「看身份」阶段清空会作废本轮并退回大厅（因为身份已经发下去了，重开更公平）。

**投票时有人掉线，卡在等投票怎么办？**
房主点「提前结束投票并结算」，没投的算弃权。

**这样别人能偷看我的身份吗？**
接口只返回请求者自己的角色，房间快照里没有别人的角色字段，结算之前也不会下发票数。但截图、共享屏幕这类社交层面的泄露防不住。

**房间码会被别人猜到吗？**
4 位数字，纯朋友局够用。介意的话只把邀请链接发群里。

**服务重启了会怎样？**
房间存在内存里，重启即清空。页面会提示「会话已失效」，重新开一间房即可。

**两种模式能中途换吗？**
不能。模式在建房时选定，跟着房间走；想换模式就重开一间房。加入的人不用选，自动跟随房间的模式。

**多内鬼模式怎么算谁赢 / 谁发红包？**
房主在结算页点一下哪队赢了，App 就按**每个内鬼单独算**：
内鬼所在队赢了，或该内鬼被投出（本队最高票里的内鬼，可并列）→ 该内鬼发 5 个红包，
总额 = 6 − 内鬼数量（5 人 1 元 / 4 人 2 元 / 3 人 3 元 / 2 人 4 元），由己方平民 + 对方内鬼共 5 人领；
内鬼所在队输了且没被投出 → 该内鬼免罚。**平民不参与发红包**。

**经典模式的红包清单怎么算？**
房主在结算页（投票阶段也可以）点一下哪队赢了，App 就按单倍规则算出清单：
内鬼所在队赢了或内鬼被投出 → 内鬼发 5 个红包（共 5 元），由己方 4 个平民 + 对方内鬼一人领 1 元；
内鬼所在队输了且没被投出 → 内鬼免罚，己方没投中他的平民每人给他 1 元（弃权也算没投中）。
当前是单倍结算，没有算「被投出双倍」；多内鬼模式暂不支持这块。

## 接口一览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/rooms` | 创建房间（可带 `mode`: `classic` / `multi`，缺省经典），返回房间码和本人的身份令牌 |
| `GET` | `/api/rooms?code=1234` | 查房间的空位（公开信息，只有座位和昵称） |
| `POST` | `/api/join` | 加入房间，占一个座位 |
| `GET` | `/api/state?token=...` | 拉取状态，**只包含本人的角色** |
| `POST` | `/api/action` | 开始本轮 / 确认身份 / 开始投票 / 投票 / 提前结算 / 录比赛结果 / 清空座位 / 回到大厅 / 退出 |
| `GET` | `/healthz` | 健康检查，返回房间数和运行时长 |

## 测试

```bash
npm test          # 等价于 node test/rules.test.js
```

部署到线上之后，可以用自检脚本对着真实网址开一局 10 人局，把规则和隐私全部验一遍：

```bash
node test/verify-deployed.js https://你的网址.onrender.com
```

它会检查服务存活、首页可访问、两个互不相干的人能各自当房主、开局前身份保密、
每队各一名内鬼、平民只能投本队、内鬼只能猜对面 5 人、内鬼票不计入、平票内鬼胜出、
十张票里只有八张有效、历史战绩写入并在新一轮里依然可查、开新一轮，
跑完打印通过项数，并把自己占用的座位退掉。

覆盖 12 项：四种判定（抓到内鬼 / 平票 / 投错人 / 无人投票）、B 队计票、
本队内鬼那一票不计入本队、对面内鬼那一票计入本队（一队共 5 票）、那一票能打破平票、
随机不越界，一局 10 人的完整流程（含「非房主不能开局」「平民不能投别队」「不能投自己」
「内鬼不能投本队、只能猜对面 5 人」「结算后不能再投」「历史战绩写入并跨轮保留」，
以及「看身份阶段任何人的响应里都不能出现全员身份」这条关键断言），
再加一组边界情况：座位被占、房间码不存在、人没到齐不能开局、开局后不能加入、
看身份阶段清空座位会作废本轮、房主退出自动移交。

多内鬼模式另有 6 项：抽签两队数量相同且 2~5 名、同队不重复、每队 10 票（平民 2 票 + 对面内鬼 2 票）、
并列时所有最高票内鬼都被标出、最高票是平民时不产出「票数最高的内鬼」、未知模式回落经典，
以及一局 10 人的完整流程（含「必须一次选满 2 票」「两票不能投同一人」「平民不能投别队」
「内鬼不能投本队」「内鬼的票计入对面」「结算才公开全部内鬼」「历史战绩记录当时的内鬼名单」）。
红包清单另有 3 项测试：经典模式投票阶段录赢家、两队内鬼都被投出都发 5 个红包、改赢家实时重算并同步历史；
经典模式输了且没被投出的内鬼免罚、漏投的平民每人给他 1 元；
多内鬼模式赢队内鬼按人数递减发 5 个包（总额 6−人数）、领包人为己方平民 + 对方内鬼、平民不发。测试合计 21 项。

> 注意：`test/verify-deployed.js` 目前只自检**经典模式**的线上表现（不传 `mode`，走的也是经典模式）。

## 一些实现取舍

- **身份只下发本人**：房间对象里存着全部内鬼的座位号，但序列化给某个玩家时会按请求者过滤，只保留他自己的角色。
- **模式跟着房间走**：`mode` 存在房间对象里（`classic` / `multi`），抽签、投票限制、计票、结算展示都按模式分叉；
  经典模式的判定规则原样保留，两种模式共用同一套房间、身份下发和轮询机制。
- **轮询而不是 WebSocket**：10 人牌局 1.2 秒拉一次状态完全够用，省掉了连接管理和断线重连的一堆状态。后台标签页降到 3 秒。
- **内存存储**：一局十几分钟，重启就重开，不值得为它引入数据库。
- **房间 6 小时无活动自动清理**，最多同时存在 500 个房间。
