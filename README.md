# 内鬼模式（LoL 内战版）

给 5v5 内战用的内鬼分配 + 赛后投票网页。10 个人各开各的页面，靠一个 4 位房间码进同一间房；
**全部身份只存在服务端，接口只把「你自己的身份」下发给你本人**，别人在任何网络响应里都查不到你的角色。

零依赖：只用 Node 内置模块，不需要 `npm install`，没有构建步骤。

## 当前规则

- 1–5 号是 A 队，6–10 号是 B 队，**每队各随机一名内鬼**。
- 两个内鬼**互相不知道**对方是谁。
- 身份只有本人能看到，猜不到也查不到别人的。
- 游戏结束后**队内投票**，每人只能投本队其他人，不能投自己。
- 内鬼**照常投票，但那一票作废**，不计入任何人的票数。
- **唯一最高票正好是内鬼** → 平民胜出；**平票 / 最高票是平民 / 无人投票** → 内鬼胜出。
- **允许连续当内鬼**，每轮完全独立随机，不做任何排除。

## 本机跑起来（30 秒）

需要 Node 18 或更高版本。

```bash
cd lol-spy
node server.js
```

打开 http://localhost:3000 就能用。Windows 上也可以直接双击 `start-windows.bat`。

局域网内其他人访问 `http://你的内网IP:3000`（注意放行防火墙）。要让外网的朋友进来，看下面的部署部分。

## 部署到公网

> 想直接拿到一个"发给谁都能用"的网址，照着 [DEPLOY.md](DEPLOY.md) 走就行，那份是按步骤点的清单。

### 路线 1：Render 免费实例（推荐，长期可用）

1. 把 `lol-spy` 目录推到一个 GitHub 仓库（公开或私有都行）。
2. 到 [render.com](https://render.com) 注册（可以直接用 GitHub 账号登录）。
3. 点 `New +` → `Web Service`，选上刚才的仓库，然后填：
   - **Runtime**：`Node`
   - **Build Command**：留空（没有依赖要装）
   - **Start Command**：`node server.js`
   - **Instance Type**：`Free`
4. 等一分多钟，拿到形如 `https://lol-spy-xxxx.onrender.com` 的地址，发群里就行。

仓库里带了一份 `render.yaml`，用 `New +` → `Blueprint` 选仓库也能直接读这份配置。

免费实例的两点注意：

- **15 分钟没人访问会休眠**，下一次访问要等 30–60 秒冷启动。游戏进行时只要有人开着页面（哪怕在后台标签页），轮询就会让它保持清醒。
- **休眠唤醒或重新部署都会清空内存里的房间**，那个房间码随之失效，重新开一间即可。
- **必须保持单实例**，不要开多实例 —— 房间状态在内存里，多实例会各存一份。

### 路线 2：零注册，房主本机开 + 隧道（最快）

不用注册任何账号，适合临时开黑：

```powershell
# 1) 本机启动服务
node server.js

# 2) 另开一个窗口，装隧道工具并穿透（Windows）
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:3000
```

终端会打印一个 `https://xxxx.trycloudflare.com` 地址，把它发群里。
缺点是房主电脑必须一直开着，而且隧道地址每次重启都会变。

### 路线 3：Docker / 其它云主机

仓库带 `Dockerfile`，任何支持容器或 Node 的平台（Fly.io、Railway、Zeabur、腾讯云轻量、阿里云等）都能跑：

```bash
docker build -t lol-spy .
docker run -p 3000:3000 lol-spy
```

服务读取 `PORT` 环境变量，默认 3000。

## 一局怎么走

1. 房主点「创建房间」，把房间码或邀请链接发群里。
2. 其他人打开链接（房间码会自动填好）→ 选一个空座位 → 填昵称 → 加入。
3. 10 个人到齐后，房主点「开始第 1 轮」。每队随机出一名内鬼。
4. 每个人点开「点击查看我的身份」看自己的角色，点「我记住了，确认身份」，然后**就可以去开游戏了** —— 这一步只是发牌。
5. 打完回来，房主点「进入投票阶段」（要等 10 个人都确认过身份这个按钮才会亮）。
6. 每人投本队里自己怀疑的人。提交后不能改，投票过程中**不显示任何票数**，避免跟风。
7. 10 个人都投完会自动结算；也可以由房主「提前结束投票」，没投的按弃权处理。
8. 结算页显示两队的票数排行、真正的内鬼是谁、判定结果，以及可展开的投票明细（含哪张票被作废）。
9. 房主点「开始新一轮」→ 重新随机内鬼，所有人自动回到看身份页面，**不用重新加房间**。

## 常见问题

**刷新页面会丢身份吗？**
不会。座位和身份绑定在浏览器的本地存储上，同一个浏览器打开同一地址会自动回到房间。

**换设备 / 清了浏览器数据怎么办？**
换设备后拿不回原来的座位，得让房主在大厅或结算阶段点座位右上角的 `×` 清空，然后再加入。

**有人中途退赛怎么办？**
房主可以在大厅、看身份、结算阶段清空那个座位。在「看身份」阶段清空会作废本轮并退回大厅（因为身份已经发下去了，重开更公平）。

**投票时有人掉线，卡在等投票怎么办？**
房主点「提前结束投票并结算」，没投的算弃权。

**这样别人能偷看我的身份吗？**
接口只返回请求者自己的角色，房间快照里没有别人的角色字段，结算之前也不会下发票数。但截图、共享屏幕这类社交层面的泄露防不住。

**房间码会被别人猜到吗？**
4 位数字，纯朋友局够用。介意的话只把邀请链接发群里。

**服务重启了会怎样？**
房间存在内存里，重启即清空。页面会提示「会话已失效」，重新开一间房即可。

## 接口一览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/rooms` | 创建房间，返回房间码和本人的身份令牌 |
| `GET` | `/api/rooms?code=1234` | 查房间的空位（公开信息，只有座位和昵称） |
| `POST` | `/api/join` | 加入房间，占一个座位 |
| `GET` | `/api/state?token=...` | 拉取状态，**只包含本人的角色** |
| `POST` | `/api/action` | 开始本轮 / 确认身份 / 开始投票 / 投票 / 提前结算 / 清空座位 / 回到大厅 / 退出 |
| `GET` | `/healthz` | 健康检查，返回房间数和运行时长 |

## 一些实现取舍

- **身份只下发本人**：房间对象里存着两个内鬼的座位号，但序列化给某个玩家时会按请求者过滤，只保留他自己的角色。
- **轮询而不是 WebSocket**：10 人牌局 1.2 秒拉一次状态完全够用，省掉了连接管理和断线重连的一堆状态。后台标签页降到 3 秒。
- **内存存储**：一局十几分钟，重启就重开，不值得为它引入数据库。
- **房间 6 小时无活动自动清理**，最多同时存在 500 个房间。
